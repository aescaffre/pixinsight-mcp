### 1. NO RINGING ARTIFACTS
HDRMT and aggressive sharpening create concentric ring patterns around bright cores/stars.
- Use `check_ringing` after EVERY HDRMT application to verify
- **Revert the operation if check_ringing reports >=3 oscillations** (galaxies with natural radial profiles may show fewer; those are a warning, not a failure).
- If oscillations >= 3: IMMEDIATELY revert and use tighter mask or donut mask technique
- Donut mask: apply `$T*(1-$T)*4` to luminance mask — protects BOTH core and background
- Prevention: mask clip_low >= 0.35 for HDRMT, or donut mask for bright cores

### 2. STARS — NOT APPLICABLE
Starless deliverable: no star layer is blended, so the stars_brightness / stars_fwhm / star_field rows do not apply; do not build or blend stars.

### 3. NO BURNT REGIONS
No extended region of the image may lose detail — cores, bright nebula, nothing. The scan uses 50×50px blocks (stars rarely false-positive); only EXTENDED regions count. Limits: burn_clip and bright_blocks rows of the gate table; bright_blocks uses the profile `burn.max_bright_block_pct` (2% for this class).
- A few bright blocks under the limit around a galaxy core are fine (warning only); extended regions above 0.80 are gated by that limit. A bright core WITH visible detail beats a clamped flat blob; hundreds of bright blocks across a shell fail.
- Run `scan_burnt_regions` after ANY tone change, on EVERY branch candidate and not only on compositions: stretch (`seti_stretch`), curves/levels brightness/contrast, LHE/HDRMT/`multi_scale_enhance`, palette/hue changes, saturation boost.
- Any branch with max > 0.90 is burnt; check per-branch max BEFORE composition (a burnt branch contaminates every composition built on it).
- Fix extended bright regions with `continuous_clamp` (min_clamp=0.75, max_clamp=0.90, soft mode, headroom=0.12 keeps ~0.12 of range above the knee) or when preview inspection confirms detail loss. Prep already stretched to median 0.12 with headroom 0.08; planetary nebulae: L stretch 0.25 max.

### 4. NOISE — gentle linear pass + ONE real final pass (do BOTH, don't skip the final)
The correct pattern is a gentle linear NXT in prep PLUS a final NXT after the heavy non-linear work. The faint-IFN reveal (lift_dust / inject_l_ifn) AMPLIFIES dust grain, and that grain lands on the dust band — exactly where the dark-sky noise metric is blind. So a final pass is REQUIRED for dust/reflection targets, not optional.
- Prep applies a GENTLE linear NXT from the profile (e.g. 0.15 for reflection, to preserve faint L IFN). It does NOT clean the grain the later dust-lift adds.
- **MANDATORY final NXT for reflection/IFN/dust targets**: after the last lift_dust / inject_l_ifn and curves, run `run_nxt` denoise=0.30, detail=0.10 on the composition before finish. `check_noise` reports BOTH dark-sky bgNoise AND dust-band dustNoise (noise_bg / noise_dust rows) — the finish WILL reject grainy dust. run_nxt is allowed in finalize.
  **run_nxt's result line IS the noise measurement** (`bgNoise=… dustNoise=… PASS/FAIL`): no separate check_noise is needed right after it; call check_noise only after blend_images, lift_outer_disc, lift_dust, inject_l_ifn or lrgb_combine.
- Branch-level passes: 0.25-0.35 through masks (post-LHE/HDRMT cleanup).
- **Avoid PLASTIC over-smoothing** — one well-placed final pass at 0.30, not repeated global denoising. The failure is BOTH extremes: grainy dust AND plastic mush.

### 5. SATURATION — NATURAL COLOR, NEITHER WASHED NOR SYNTHETIC
Saturation must match the object type. Broadband galaxies: warm, muted, subtle gradients. Emission objects: vivid is natural. Over-saturation looks synthetic. Limit: saturation row of the gate table (profile max_p90 = 0.85: dial back above it; FAIL beyond the table limit).
- run_curves on channel S/RGB and inject_luminance already return the subject P90 saturation vs the profile limits in their result line — that IS the saturation measurement. A separate `check_saturation` is only needed after blend_images or lrgb_combine.
- Use `check_saturation` after EVERY saturation boost, curves, hue_boost
- **`check_saturation` IMMEDIATELY after lrgb_combine** — LRGB often amplifies saturation dramatically
- Check on the STARLESS composite BEFORE star blend — this is where you fix it
- Dust lanes are ABSORPTION features — they should be dark/muted, not vivid red/orange
- **FIX SATURATION UPSTREAM, NEVER DOWNSTREAM:** if `check_saturation` fails after `lrgb_combine`, do NOT desaturate the combined result (post-hoc desaturation kills the colour gradients of the original channels). Restore from backup, reduce the LRGB `saturation` parameter (e.g. 0.80 → 0.60 → 0.40) and re-combine. This applies to ANY composition step: when a quality gate fails, adjust the upstream parameters, not the downstream result.


### 6. TONAL PRESENCE — SUBJECT MUST BE IMPACTFUL
Use `check_tonal_presence` on composition candidates BEFORE star blend. Limit: tonal_presence row of the gate table.
- **Subdued** (below the limit): restore pre-star checkpoint, apply ONE subject-masked midtone lift, re-blend
- **Balanced** (limit to 8×): good — subject is tonally impactful
- **Aggressive** (>8×): check for burns in bright areas
- Deterministic ROI-based measurement, not visual impression; low ROI confidence → advisory only (few subject pixels detected)
- This catches images that are technically safe but flat — a dim galaxy that passes the brightness gate but doesn't STAND OUT from the background


### 7. HIGHLIGHT TEXTURE — SHELL DETAIL MUST SURVIVE PROCESSING
Bright emission shells can appear "burnt" at moderate brightness (0.40–0.73) if internal
tonal variation has collapsed into a featureless plateau. This is **perceptual burn**.

**PRIMARY SIGNAL: RELATIVE texture retention vs reference checkpoint (blocking).**
- BEFORE any operation that damages shell texture (clamp, detail tool):
  create a clone: `clone_image` (e.g., "pre_clamp_COMP_boldcolor")
- `clone_image` is for short-lived rollback inside a step; for long-lived references (pre_clamp/pre_detail/pre-star) `save_variant` then `close_image`, and `load_variant` on demand; keep <=6 full-res windows open.
- AFTER the operation: `check_highlight_texture(view_id=..., reference_id="pre_clamp_...")`
- **ADVISORY** (blocking only when the profile sets highlight_texture.blocking): textureRetention < 40% on any metric = warning (>60% of texture destroyed)
- **WARNING**: textureRetention < 60%
- WITHOUT reference: advisory only (absolute heuristics, never blocking)

**Reference checkpoints — clone BEFORE which operation:**
- Before continuous_clamp → `pre_clamp_{comp}`
- Before shell_detail_enhance → `pre_detail_{comp}`

**WHEN THIS GATE FAILS:**
- After clamp: RESTORE pre-clamp. If absolute burn gates pass without clamp: SKIP clamp.
  Otherwise: raise knee +0.08, increase headroom +0.04. After 2 attempts: accept brighter image.
- After detail tool: If multi_scale_enhance was used: SWITCH to shell_detail_enhance.
  If shell_detail_enhance: reduce amounts by 30%. Do NOT clamp harder.

**DETAIL TOOL FOR EMISSION SHELLS:**
- Do NOT use `multi_scale_enhance` on bright emission shells. LHE equalizes local histograms,
  pushing bright shell pixels toward clipping, forcing destructive clamping.
- Use `shell_detail_enhance` instead — it extracts detail at filament scale and amplifies it
  while PRESERVING the smooth brightness component. Brightness-neutral by design.
- Use `create_adaptive_zone_masks` for ROI-anchored zone masks (core/shell/outer).

**PREFERRED PROCESSING ORDER FOR SHELL EMISSION NEBULAE:**
1. Gentle highlight protection if burn gates require it (check first, skip if unnecessary)
2. Adaptive zone masks within subject ROI
3. `shell_detail_enhance` through shell mask — texture enhancement within the established range
4. Zone-specific curves, check_highlight_texture at each step
5. Finish gates
The agent may deviate from this order if justified, but this avoids the detail→burn→clamp→flatten cycle.
